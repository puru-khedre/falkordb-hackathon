The problem

Agents can read your code. They can't read your context.

An AI assistant happily rewrites a shared function, hallucinates a library you already replaced, or violates the architecture rule decided in a Slack thread two years ago. It never sees the 12 callers downstream, the "max 50% discount" rule, or that Priya owns this file. Flat .cursorrules files rot. ContextAnchor turns your codebase into a graph the agent can actually query.

How it works

Three questions, one graph, all three tracks

Every answer is a FalkorDB traversal or native graph algorithm — remove the graph and the product stops working.

TRACK 1 — ACT ON DATA

What breaks?

Multi-hop CALLS traversal finds every upstream caller and live API endpoint, and algo.betweenness scores the real chokepoints.

TRACK 2 — AGENT MEMORY

What rule forbids it?

Team rules and architecture decisions live as graph nodes — persistent memory the agent checks on every change, not a file that goes stale.

TRACK 3 — COMPANY BRAIN

Who owns it, and why?

Ownership comes from real git log history, linked to the ADR that explains why the code is the way it is.

place_order→ checkout→ create_invoice→ calculate_discount

ContextAnchor documentation

The missing context layer for AI-assisted coding — powered by a FalkorDB graph.

Overview

ContextAnchor turns a codebase into a graph and answers three questions before any change is made: what breaks (blast radius), what rule it violates (team memory), and who owns it (from git history). The same graph powers a web dashboard, a CLI gate, a GitHub PR bot, and an MCP server your AI agent calls directly.

It unifies all three Graph Hacks tracks — Act on Connected Data, Agent Memory, and Company Brain — on one FalkorDB graph.

Quick start

git clone <your-repo-url> && cd contextanchor
docker compose up --build

Open http://localhost:8000 (dashboard) and http://localhost:9000/sse (MCP). A sample microservices graph auto-seeds on first boot no API key, no setup. Add an LLM key later from Settings for AI-written summaries.

Offline-safe: without an LLM key, every verdict still comes straight from FalkorDB (graph mode). The LLM only adds a natural-language summary.

Core concepts

The graph model

NodeMeaning
File / FunctionCode structure. Functions are keyed by fid = file::name so same-named functions never merge.
EndpointAn HTTP route (FastAPI/Flask/Express) that executes a function.
DeveloperCode owner, derived from real git log history.
TeamRuleAn architecture/convention rule — persistent agent memory.
ADRArchitecture Decision Record — the "why".

Relationships: CONTAINS, CALLS, EXECUTES, AUTHORED, GOVERNS, APPLIES_TO.

Verdicts

BLOCK (a HIGH-severity rule applies) · REVIEW (3+ callers or a live API affected) · SAFE (leaf, no rules).

A worked example

Your agent wants to edit calculate_discount(). ContextAnchor runs the blast-radius traversal:

MATCH (t:Function {fid: 'billing_service.py::calculate_discount'})
MATCH p = (caller:Function)-[:CALLS*1..3]->(t)
RETURN DISTINCT caller.name, min(length(p)) AS hops
ORDER BY hops;

→ create_invoice (1 hop), checkout (1), place_order (2). Two endpoints reach those callers (GET /invoices, POST /checkout). A GOVERNS edge finds RULE-4 (HIGH) "discounts can't exceed 50%". Result: verdict = BLOCK, owner Arjun Rao (from git), decision ADR-07. The agent now has everything it needs to avoid breaking the change — all from one graph, in milliseconds.

The dashboard

Left sidebar, top to bottom: Codebase (pick a project / ingest), Check a change (type a function), Ask this project, Try it (sample scenarios + guided tour), and Advanced (rules, CLAUDE.md export). The centre shows a live project overview with the riskiest chokepoints — click one to inspect its impact as a focused graph.

Ingesting repos

Paste a GitHub URL or a local path in Codebase — Ingest, or use the CLI:

docker compose exec web python -m app.ingest --repo https://github.com/user/repo

Languages: Python (precise, via ast) and JS/TS/Go/Java (approximate, regex). Ownership comes from the repo's git history.

Private repos: add a GitHub token in Settings once, then ingest private URLs the same way.

Grounded Ask

The Ask this project box answers natural-language questions ("what handles billing?") using only facts retrieved from the graph (matching functions + their docstrings, rules, chokepoints), so the LLM stays grounded and can't hallucinate.

Settings

In Manage — Settings you configure one LLM (NVIDIA NIM key, base URL, model) and a GitHub token. Values are stored in FalkorDB and shown masked. Environment variables (NVIDIA_API_KEY, GITHUB_TOKEN) are used as fallback.

Tutorial 3 — Connect your AI agent (MCP)

ContextAnchor is an MCP (Model Context Protocol) server. Any MCP-capable coding agent can call its seven tools to pull real context from the FalkorDB graph before it edits your code. Pick the transport your client prefers:

TransportEndpoint / commandBest for
SSE (running from docker compose)http://localhost:9000/sseClaude Code, Cursor, Windsurf
stdio (client launches the process)python -m app.mcp_server --stdioClaude Desktop, offline/local
Prerequisite: for SSE, keep docker compose up running — the mcp container serves :9000 and FalkorDB serves :6379. Check it first: curl -N http://localhost:9000/sse should open a stream and stay connected.

Claude Code

One command registers the server (SSE):

claude mcp add --transport sse contextanchor http://localhost:9000/sse

Verify with claude mcp list (should read contextanchor: connected); inside a session run /mcp to see the seven tools. To share it with your team, commit a project-scoped .mcp.json at the repo root:

{
  "mcpServers": {
    "contextanchor": { "type": "sse", "url": "http://localhost:9000/sse" }
  }
}

Cursor

Create or edit ~/.cursor/mcp.json (global) or .cursor/mcp.json (this project only):

{
  "mcpServers": {
    "contextanchor": { "url": "http://localhost:9000/sse" }
  }
}

Open Cursor Settings → MCP: contextanchor should show a green dot and 7 tools. Toggle it on.

Claude Desktop

Edit the config file (create it if missing), then fully restart Claude Desktop:

OSPath
macOS~/Library/Application Support/Claude/claude_desktop_config.json
Windows%APPDATA%\Claude\claude_desktop_config.json

Claude Desktop launches MCP servers over stdio, so bridge the SSE endpoint with mcp-remote (no extra install — npx fetches it):

{
  "mcpServers": {
    "contextanchor": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:9000/sse"]
    }
  }
}

After restart the tools appear under the tools (🔌) menu in the message box. Prefer launching the server directly over stdio instead? See Run without Docker.

Use it

Ask your agent, in plain language:

Use contextanchor to analyze_change on calculate_discount before you edit it.

The agent calls the tool and gets back structured, graph-grounded context:

{
  "verdict": "BLOCK",
  "project": "contextanchor_sample",
  "blast_radius": {
    "callers": [
      {"name": "create_invoice", "file": "billing_service.py", "hops": 1},
      {"name": "checkout",       "file": "order_service.py",   "hops": 1},
      {"name": "place_order",    "file": "order_service.py",   "hops": 2}
    ],
    "endpoints": ["POST /checkout", "GET /invoices"]
  },
  "rules": [{"id": "RULE-4", "severity": "HIGH", "rule_text": "Discounts can't exceed 50%"}],
  "owner": {"name": "Arjun Rao", "commits": 14, "adr": "ADR-07"},
  "chokepoint": {"name": "calculate_discount", "score": 0.81},
  "recommendation": "BLOCK — RULE-4 (HIGH) governs this; 3 callers and 2 live endpoints depend on it. Loop in Arjun Rao."
}

Now the agent writes the compliant change instead of breaking three teams.

Testing from Python? Use the official MCP SDK client (from mcp.client.sse import sse_client) — the stand-alone fastmcp client has a pydantic incompatibility with this server.
Tools not showing up? (1) Confirm the stream: curl -N http://localhost:9000/sse. (2) Fully quit and reopen the client (a reload isn't always enough). (3) For stdio, FalkorDB must be reachable — set FALKORDB_HOST=localhost and keep docker compose up running. (4) "Ambiguous function name" → pass the full fid (file::name), e.g. billing_service.py::calculate_discount.

Tutorial 4 — Block risky commits (pre-commit / CI)

# one-off check (exit 1 on BLOCK)
docker compose exec web python -m app.check calculate_discount

# install the git hook
ln -s ../../integrations/git-hooks/pre-commit .git/hooks/pre-commit

Claude Code users can also drop integrations/claude-code/settings.json into .claude/ to warn the agent before every edit.

Tutorial 5 — GitHub PR impact bot

The workflow at .github/workflows/contextanchor.yml runs on every pull request: it spins up FalkorDB, ingests the repo, maps the PR diff to functions, and comments the combined blast radius, violated rules and suggested reviewers.

It needs pull-requests: write permission (already set). Set CA_STRICT=1 to fail the check on a BLOCK verdict.

Tutorial 6 — Generate CLAUDE.md / .cursorrules

docker compose exec web python -m app.genrules --project proj_myrepo --format claude > CLAUDE.md

Or click Open CLAUDE.md under Advanced. The file is regenerated from the graph — hard rules, chokepoints to edit carefully, ownership and API entrypoints — so your agent's base context is never stale.

Architecture

Three containers via docker compose, all talking to one FalkorDB instance:

Browser (Cytoscape + dagre)          AI agent (Cursor / Claude Code)
        |  HTTP / JSON                        |  MCP over SSE
   FastAPI  web :8000                   mcp_server  :9000
        \_____________ app/agent.py _____________/
                            |
                   FalkorDB :6379   (Cypher + algo.betweenness)
                            |
              NVIDIA NIM LLM (optional; graph-template fallback)
  • Per-project graphs: every ingested repo is its own FalkorDB graph (proj_<name>); a small ca_meta graph holds the project registry and your LLM/GitHub settings.
  • Parsing: app/ingest.py Python via stdlib ast (precise), JS/TS/Go/Java via regex (approximate). Function docstrings are stored so the agent knows what code does, not just how it connects.
  • Resilience: the sample graph auto-reseeds if its schema is outdated; the LLM is always optional.

Environment variables

Set these in .env (git-ignored) or pass them to the containers. Anything you configure in Manage → Settings is stored in FalkorDB and overrides the matching variable.

VariableDefaultPurpose
FALKORDB_HOSTfalkordb (in compose) / localhostFalkorDB host. Use localhost when running a process outside Docker.
FALKORDB_PORT6379FalkorDB port (published by docker compose).
NVIDIA_API_KEY(empty)Optional. Enables LLM-written summaries. Blank = offline graph mode.
NVIDIA_BASE_URLhttps://integrate.api.nvidia.com/v1OpenAI-compatible LLM endpoint.
NVIDIA_MODELmeta/llama-3.2-11b-vision-instructModel used for narration / grounded Ask.
GITHUB_TOKEN(empty)Clone private repos (needs repo read scope).
MCP_HOST / MCP_PORT0.0.0.0 / 9000Where the MCP SSE server binds.

Never commit .env — your NVIDIA key and GitHub token live there and it is already git-ignored.

Run without Docker (local stdio)

For Claude Desktop's direct-stdio config, or local development, run the MCP server as a plain process. FalkorDB still has to be reachable — the simplest path is to let docker compose up run it on :6379:

pip install -r requirements.txt
FALKORDB_HOST=localhost python -m app.mcp_server --stdio

Claude Desktop config that launches it directly (no mcp-remote bridge):

{
  "mcpServers": {
    "contextanchor": {
      "command": "python",
      "args": ["-m", "app.mcp_server", "--stdio"],
      "cwd": "/absolute/path/to/contextanchor",
      "env": { "FALKORDB_HOST": "localhost", "FALKORDB_PORT": "6379" }
    }
  }
}

Troubleshooting & FAQ

A function shows "No upstream callers"

It's a leaf — nothing calls it — so changing it is SAFE. That's correct, not a bug.

Two functions share a name

Functions are keyed by fid = file::name. Pick the exact one from the dropdown (it shows name · file).

My ingested repo looks wrong after an update

Re-ingest it from Manage → Refresh older graphs may predate the fid/doc fields.

The MCP container won't start

Ensure fastmcp>=2 is installed and rebuild: docker compose build --no-cache mcp. Test with the official MCP SDK client (mcp.client.sse), not the stand-alone fastmcp client.

A private repo won't clone

Add a GitHub token with repo read scope in Settings, then ingest the private URL.

Does it support languages other than Python well?

Python is precise (AST). JS/TS/Go/Java use a lightweight regex pass — good for structure, occasionally approximate on call attribution. Full multi-language (tree-sitter) is on the roadmap.
